# brief — 진행 현황 브리핑

독자는 프로젝트의 주제는 알지만 협업 과정·파일·도구는 모르는 사람입니다. 인자는 받지 않습니다. 진행사항(A부)과 인사이트(B부)를 한 답변에 이어서 씁니다.

**범위**: 읽고, 확인하고, 설명하는 것까지입니다. 파일 수정, 문서 갱신, 작업 재기동, 백그라운드 프로세스, 다른 에이전트 지시는 하지 않습니다. 문서만 읽고 "가동 중"이라 쓰지 않습니다.

**경로**: 아래 경로는 프로젝트 루트 기준입니다. 하위 디렉토리에서 시작했으면 루트를 먼저 찾습니다.

## 1단계: 근거 (읽기 전용, 독립 호출은 한 응답에 묶기)

1. `date`로 현재 시각을 잰다.
2. `agent-guide/SESSION.md`의 "현재 상태"·"다음 작업" 칸. 정본 기록(랩노트·계획서·리포트)과 진행 로그의 경로는 여기서 얻는다. `agent-guide/`가 없으면 `README.md`와 최근 갱신된 문서로 대신한다.
3. 정본 기록의 머리 블록, 결과 표, 최근 항목 3~5개, 확정·미확정 구분("쓸 수 있다 / 쓸 수 없다" 류).
4. 진행 로그(라운드 로그·세션 이력 등) 마지막 2~3항목. 최근 결정·사고 확인용이며 내용을 옮기지는 않는다.
5. 문서가 "실행 중"이라 말하는 작업(실험·배치·학습·서버)이 있으면 실측한다: 큐·상태 파일, `ps`로 프로세스 생존, GPU 작업이면 `nvidia-smi`의 메모리(util%는 쓰지 않는다), 진행 파일 마지막 줄. **위치는 SESSION.md나 정본 기록 머리 블록에 적힌 것만 쓴다.** 적혀 있지 않으면 추측하지 말고 "위치 미기재"로 보고하고 상태는 "미확인"으로 둔다. 문서와 실측이 다르면 실측이 정본이다.

부호·방향 문장("켜면 줄어든다", "A가 B보다 크다")은 기록의 수치 표를 직접 읽어 확인한 뒤 쓴다. 기억이나 요약본으로 방향을 쓰지 않는다.

## 2단계: 쓰기

### 공통 규칙 — 내용만, 과정은 뺀다

- **넣는 것**: 질문(목표), 장면, 결과 수치와 그 뜻, 확정된 것과 후보로 남은 것, 사전 예측과 판정 기준, 지금 돌아가는 작업의 상태와 예상 시각, 다음 단계.
- **빼는 것**: pid·파일명·경로·SHA·도구 이름, 회신·라운드·판본 번호, 수용·기각 건수 장부, 내가 방금 한 작업의 나열, 메시지·문서 갱신 사실. 사고는 원인 한 문장과 일정 영향 한 문장까지만.
- **문체**: 개조식이 기본. 문단 대신 불릿, 불릿 하나에 문장 하나(길어야 둘). 한 문장 40자 안팎, 접속·부연·괄호 보충으로 이어 붙이지 않는다. 비유·의인화, "역설·반전·놀라움" 프레임 금지. 기술 용어는 첫 등장에 한 줄 풀이.
- **수치**: 표에 모으고 산문에는 값을 반복하지 않는다. 산문은 "무엇이 무엇보다 큰가, 0과 구별되는가"로 쓴다.
- **분량**: A부는 불릿 10개 안팎에 표 1개, 아스키 그림 2개까지. B부는 번호 항목 3~5개, 항목당 주장 한 줄에 근거 불릿 1~2개, 15줄 안쪽. A부의 표 해석은 결과 사실까지만 쓰고 해석·후보 논의는 B부로 넘겨 중복을 피한다.

### A부 — 진행사항

```
## 📋 지금 무엇을 하고 있는가
  질문(목표) 한 문장 + 고정한 것·바꾸는 것 불릿 2개
  아스키 장면(무엇이 어디서 움직이는가, 경계, 판독량 정의 한 줄. 실험이 아니면 구성도)
  핵심 발견 흐름 — 표 (대상 × 판독량. 개발 작업이면 항목 × 상태. 진행 중 칸은 "실행 중/대기")
  표의 뜻을 불릿 2개로 (무엇이 나왔고 무엇이 판정 전인가. 해석은 B부에서)

## 🔬 지금 돌아가는 것
  아스키 큐 트리(블록별 완료 ✅ / 실행 중 ⏳ / 대기, 실측 시각과 자원 한 줄). 없으면 "가동 중인 작업 없음" 한 줄
  불릿: 예상 시각 / 사고가 있었으면 원인 한 줄·영향 한 줄
  사전 예측 불릿: 예측값 / 맞으면 성립하는 것 / 틀리면 뜻하는 것

## 🤝 다음 손
  참여자가 둘 이상(Codex·GPT Pro 등)이면 각자 다음에 무엇을 하는지 한 줄씩, 혼자면 다음 단계 한 줄. "그 다음" 한 문장
```

### B부 — 인사이트 (A부에 바로 이어서)

```
## 💡 지금까지의 인사이트
  **1. 굵은 한 문장 주장.**
    - 근거 한 줄(수치는 방향과 유의성만). 배제된 후보·남은 후보는 같은 줄에 짧게. 아스키 식은 꼭 필요할 때 한 줄
  **2. …** (3~5개. 확정과 후보를 문장 안에서 구분: "…입니다" / "…후보로 남았습니다". 방법론 교훈은 결과가 아니면 뺀다)
  **주장할 수 있는 것**: 한 줄
  **아직 못 하는 것**: 한 줄 + 무엇이 오면 풀리는지
```

## 에러 처리

- SESSION.md가 정본 기록·진행 로그를 가리키지 않음: 최근 갱신된 문서로 대신하되 출력 첫 줄에 "정본 미지정"이라 밝힌다
- 실측 대상 위치 미기재·프로세스 미발견: 그 칸을 "미확인"으로 두고 문서 상태를 그대로 옮기지 않는다
