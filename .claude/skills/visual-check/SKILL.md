# 시각 검증

UI 코드는 텍스트로 읽어서는 결과를 알 수 없습니다. 카드가 겹치는지, 모바일에서 가로 스크롤이 생기는지, 웹폰트가 폴백으로 바뀌었는지는 렌더링한 화면을 봐야 압니다. 이 스킬은 **찍기 → 보기 → 판단 → 고치기 → 다시 찍기** 루프를 돌립니다. 스크린샷을 찍었다는 사실이 아니라, 찍은 이미지를 실제로 읽고 내린 판단이 결과물입니다.

## 1. 준비

```bash
bash ~/.claude/skills/visual-check/scripts/setup.sh --check   # 상태만 확인
bash ~/.claude/skills/visual-check/scripts/setup.sh           # 없는 것만 설치 (playwright 전역 패키지 + Chromium)
```

설치는 사용자 권한으로 끝나지만, Chromium이 요구하는 시스템 라이브러리와 한글 폰트는 관리자 권한이 필요합니다. 실행 시 `libasound.so.2` 류의 공유 라이브러리 오류가 나거나 스크린샷의 한글이 네모로 나오면 아래 명령을 사용자에게 안내하고, 직접 실행하지 않습니다.

```bash
sudo apt-get install -y libasound2t64 fonts-noto-cjk   # Ubuntu 24.04 기준
```

## 2. 찍기

```bash
SHOOT=~/.claude/skills/visual-check/scripts/shoot.mjs

node "$SHOOT" ./dist/index.html                       # 정적 HTML 파일
node "$SHOOT" http://localhost:3000/dashboard         # 실행 중인 개발 서버
node "$SHOOT" http://localhost:3000 --dark            # 다크 모드
node "$SHOOT" http://localhost:3000 --selector "#hero" --widths 1440 --name hero   # 특정 요소만
node "$SHOOT" http://localhost:3000 --wait 1500       # 애니메이션·지연 로딩 후 촬영
```

| 옵션 | 기본값 | 뜻 |
|------|--------|-----|
| `--out DIR` | `.visual-check` | 결과 저장 위치 |
| `--widths A,B,C` | `1440,768,390` | 촬영할 뷰포트 폭. 1440·1024·768·390은 desktop·laptop·tablet·mobile로 이름이 붙는다 |
| `--no-full` | 전체 페이지 | 첫 화면(높이 900px)만 촬영 |
| `--selector CSS` | 없음 | 해당 요소만 촬영 |
| `--wait MS` | 0 | 네트워크가 잠잠해진 뒤 추가로 기다릴 시간 |
| `--dark` | 라이트 | `prefers-color-scheme: dark`로 렌더링 |
| `--name PREFIX` | 없음 | 파일명 접두어. 수정 전후를 나눠 보관할 때 쓴다 |

개발 서버가 필요한 프로젝트는 서버를 배경 작업으로 먼저 띄운 뒤 찍습니다. 결과 폴더 `.visual-check/`는 프로젝트 `.gitignore`에 넣습니다.

### 결과물

- `<name-><label>.png`: 폭별 스크린샷
- `<name->report.json`: 폭별 진단. 문서 폭 대 뷰포트 폭, 뷰포트 밖으로 나간 요소(최대 10개), 선언된 웹폰트의 로드 상태, `body`·`h1`·`button`의 CSS `font-family`, 깨진 이미지, 콘솔 에러, 페이지 에러, 실패한 요청(네트워크 실패와 HTTP 4xx·5xx)

표준 출력에 폭별 한 줄 요약이 나옵니다. `⚠` 표시가 하나라도 있으면 리포트를 열어 원인을 봅니다. 전체 페이지 스크린샷의 가로 크기가 요청한 폭보다 크면 그 자체가 가로 넘침의 증거입니다. 시스템 서체가 없어 폴백된 경우는 리포트에 잡히지 않으므로 이미지에서 자형으로 판단합니다.

## 3. 보기

찍은 PNG를 **모든 폭에 대해** `Read`로 엽니다. 데스크톱만 보고 끝내지 않습니다. 전체 페이지 스크린샷이 길면 첫 화면과 문제가 의심되는 구간을 나눠 봅니다. `report.json`은 이미지에서 보이지 않는 것(콘솔 에러, 폰트 로드 실패, 실패 요청)을 보완합니다.

## 4. 판단

이미지를 보고 아래 항목을 하나씩 확인합니다. 코드에서 이미 확인한 항목이라도 화면에서 다시 봅니다.

| 축 | 볼 것 |
|----|------|
| 레이아웃 | 요소 겹침, 잘림, 의도하지 않은 빈 공간, 정렬선 어긋남, 섹션 간 간격 불균형 |
| 반응형 | 가로 스크롤, 고정 폭 요소, 모바일에서 여러 열이 좁게 눌린 그리드, 너무 작은 터치 대상, 잘린 내비게이션 |
| 서체 | 의도한 서체로 렌더됐는지(폴백이면 자형이 다르다), 웹폰트 미로드, 한글·영문 혼용 시 굵기·크기 불일치, 줄 길이와 행간 |
| 색·대비 | 배경 위 텍스트 판독 가능 여부, 다크 모드에서 뒤집히지 않은 색, 브랜드 색이 토큰 값과 다른 경우 |
| 이미지·아이콘 | 깨진 이미지, 비율 왜곡, 흐릿한 확대, 아이콘 크기 불일치 |
| 상태 | 콘솔 에러, 실패 요청, 로딩 중 상태로 굳은 요소 |

발견한 문제는 **폭·위치·증상·원인 추정**을 한 줄씩 적은 목록으로 만듭니다. "대체로 괜찮다"는 판단이 아닙니다.

### 기준 이미지가 있을 때

디자인 시안, Stitch 결과물, 이전 버전 스크린샷이 있으면 기준 이미지와 새 스크린샷을 같은 폭끼리 나란히 읽고 차이를 항목별로 적습니다. 레이아웃 구조, 색, 서체와 크기, 간격, 이미지 처리 다섯 축에서 구체 항목 5개 이상을 대조하고, 브리프가 허용한 차이와 허용하지 않은 차이를 구분합니다. 기준에 없는 장식(오버레이, 그라데이션, 배지, 화살표)을 구현이 임의로 추가했으면 그것도 차이입니다.

## 5. 고치기와 다시 찍기

문제 목록 순서대로 코드를 고치고, 같은 명령에 `--name after` 같은 접두어를 붙여 다시 찍어 전후를 비교합니다. 목록의 모든 항목이 화면에서 해결된 것을 확인한 뒤에 완료로 보고합니다. 보고에는 어느 폭에서 무엇을 발견해 어떻게 고쳤는지를 적습니다.

## 한계

정적 렌더링만 다룹니다. 클릭·입력·스크롤 뒤의 상태는 `--wait`과 `--selector`로 일부만 볼 수 있습니다. 상호작용 흐름 자체를 검증해야 하면 Playwright MCP 같은 브라우저 조작 도구가 필요합니다. 인증이 필요한 페이지는 개발 서버 쪽에서 인증을 우회하거나, 정적 HTML로 내보낸 뒤 찍습니다.
